# Результат проверки модуля качества Residual

Этот документ описывает отдельный модуль контроля качества и его эксперимент на 12 октября 2026 года. Основной исследовательский сценарий «вопрос → план → расчёт → справка» и актуальный запуск описаны в [README](../README.md). Модуль качества загружает D006 + D008 за 2024 год, формирует очередь, показывает основания, сохраняет решение и сравнивает версии. Исходные файлы автоматически не исправляются. Практическая польза для сотрудника БНС пока является гипотезой: эксперта и ведомственного пилота у команды нет.

## Проверка именно действующего процесса

[Протокол](benchmark_protocol.txt) зафиксирован до получения результатов. В копии полного пакета внесены изменения, затем запускается тот же `analyze_package`, который использует приложение. Модель обучается и ранжирует этот пакет. Признаки и правила не перенастраивались под желаемый результат.

Два режима × три seed (17, 29, 43). В каждом пакете изменено 348 записей: по 116 на механизм. Все методы используют одну базу из 250 записей и ещё 50 мест: следующие робастные кандидаты, кандидаты ML либо случайный отбор. Таким образом, у каждого метода ровно 300 просмотров. Гибридная очередь эксперимента совпала с очередью приложения во всех шести запусках.

| Режим: среднее по 3 запускам | Робастные 300 | База 250 + ML 50 | База 250 + случайные 50 |
|---|---:|---:|---:|
| Грубые изменения: найдено из 348 | 254,00 | 253,67 | 205,00 |
| Грубые изменения: доля найденных | 72,99% | 72,89% | 58,91% |
| Умеренные изменения: найдено из 348 | 15,67 | 13,33 | 13,33 |
| Умеренные изменения: доля найденных | 4,50% | 3,83% | 3,83% |

Грубые изменения: жилая площадь больше общей, обе площади ×10, комнаты ×8. Умеренные изменения: обе площади ×1,4, комнаты +1, доля жилой площади ±0,15 с сохранением допустимого соотношения.

На грубых сценариях 46 из 300 мест занимают исходные обязательные сигналы. Они не входят в метки внесённых изменений, поэтому доступный максимум найденных внесённых изменений — 254. Робастный метод достиг его во всех трёх запусках.

## Что дали дополнительные 50 мест

| Режим | Робастный отбор: среднее число находок | ML: среднее число находок | Случайный отбор: среднее число находок |
|---|---:|---:|---:|
| Грубые изменения | 50,00 | 49,67 | 1,00 |
| Умеренные изменения | 3,67 | 1,33 | 1,33 |

Разница ML минус следующий робастный отбор по seed: грубые **0, 0, −1**, умеренные **+1, −4, −4**. Устойчивое преимущество ML не установлено. Сравнение только со случайным отбором дало бы неполную картину.

Умеренное изменение может быть допустимым ответом, а неизменённая запись может содержать исходную проблему. Поэтому нельзя называть эти результаты точностью на реальных ошибках или считать все просмотренные неизменённые записи ложными срабатываниями. Слабое обнаружение умеренных изменений не доказывает, что система пропускает столько же реальных ошибок.

## Решение по продукту

Основу процесса составляют проверяемые условия, робастный отбор и журнал разбора. Дополнительные ML-кандидаты остаются явно обозначенной экспериментальной частью. Их дополнительная польза и приемлемые затраты ручного просмотра требуют будущей экспертной оценки. До неё нельзя обещать более точный поиск или ускорение работы за счёт ML.

Работоспособность проверена отдельно: 45 автоматических тестов прошли; в изолированном браузерном сценарии загружены CSV, подготовлен вопрос по расхождению состава, сохранено решение, загружена следующая версия. Сравнение корректно отделило одну новую обычную запись от новых сигналов и показало все 121 изменение через последовательное раскрытие и CSV. Исходная версия и решение сохранились. Это проверка реализации, не пользовательское исследование.

## Воспроизведение и ограничения

```bash
python -m src.evaluate_workspace --data-dir "../synthetic_microdata_2021-2024_20260921"
python -m unittest discover -s tests -v
```

[Полный JSON](../reports/workspace_benchmark.json) содержит параметры, версии библиотек, SHA-256 входных файлов, протокола и кода, результаты всех запусков и сравнение дополнительных находок. [CSV](../reports/workspace_benchmark.csv) содержит все 18 сочетаний «режим × seed × метод». Исходные файлы по завершении не изменились. Полный эксперимент на текущем компьютере занял 191,707 секунды; это техническое время прогона, не экономия времени специалиста.

Сценарии выбраны командой без согласования с экспертом. Три seed не заменяют независимые реальные внедрения. Данные синтетические; оценки невзвешенные, к населению Казахстана не относятся. Полезность рабочего процесса, точность на размеченных реальных ошибках и время сотрудника пока не измерены.

## Исторический результат v0.2

В первом эксперименте использовались пять разбиений 70/30 и бюджет просмотра 10% тестовой части. Правила + случайный порядок находили 37,9% грубых внесённых искажений, правила + Isolation Forest — 81,9%, правила + робастный метод — 100%. Это другой режим проверки. Его отчёты сохранены в [quality_summary.json](../reports/quality_summary.json) и [quality_benchmark.csv](../reports/quality_benchmark.csv); к нынешней очереди их метрики не приписываются.
