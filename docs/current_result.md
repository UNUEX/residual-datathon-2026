# Текущий результат

Residual помогает специалисту статистического органа быстрее находить записи, требующие проверки. Система не исправляет данные автоматически: она ранжирует записи, показывает основание сигнала и сохраняет решение аналитика.

## Данные и очередь

| Показатель | Значение |
|---|---:|
| Записи D006, связанные с D008 | 11 704 |
| Записи для обучения после известных правил | 11 658 |
| Нарушения проверяемого правила | 46 |
| Кандидаты ML в очереди | 204 |
| Размер очереди | 250 |

Все 46 нарушений — случаи, где жилая площадь больше общей. Это логическое противоречие, а не подтверждённая ошибка первичного источника.

## Проверка гипотез

Эксперимент проведён на пяти фиксированных разбиениях. В копию тестовой части внесено по 69 искажений трёх типов: жилая площадь больше общей, обе площади увеличены в 10 раз, число комнат увеличено в 8 раз. Каждый метод передаёт аналитику 350 из 3 498 записей.

| Метод ранжирования | Средняя полнота | Доля найденных среди просмотренных |
|---|---:|---:|
| Правила + случайный порядок | 37,9% | 22,5% |
| Правила + Isolation Forest | 81,9% | 48,5% |
| Правила + робастное отклонение | 100,0% | 59,1% |

Гипотеза о пользе ML по сравнению с одними правилами подтверждается на внесённых искажениях. Гипотеза о преимуществе ML над простым робастным ранжированием не подтверждается. ML полностью находит изменения площади, но обнаруживает в среднем 45,8% изменений числа комнат.

Результат относится только к контролируемому эксперименту на синтетических данных. Неизменённые записи не считаются гарантированно правильными, а метрики не показывают точность на реальных ошибках.
