RESIDUAL — ВОЗМОЖНОСТИ И ОГРАНИЧЕНИЯ MVP
Версия описания: 12 октября 2026 года. Ведомственное внедрение не проводилось.

1. Рабочая задача и результат
Аналитику нужно получить проверяемую описательную справку по готовой таблице.
Residual позволяет загрузить файл, подтвердить смысл столбцов, задать вопрос,
проверить предложенный моделью план и получить расчёт без написания кода.
Выход: таблица и диаграмма в интерфейсе, численность, пропуски, методика,
ограничения, происхождение данных и сохранённая справка. Доступны HTML, CSV,
JSON и воспроизводимый Python с исходным CSV. Автопубликации нет.
Польза в работе БНС и экономия времени остаются гипотезами: интервью и пилота нет.

2. Что сейчас работает на главном экране
Один файл CSV/TSV, Excel (.xlsx/.xls) либо HTML/HTM с таблицами.
Пользователь выбирает лист или таблицу и строку заголовков. В паспорте подтверждает
название набора, единицу наблюдения, период, названия и роли столбцов, единицы
и десятичный разделитель. Можно отметить синтетическое происхождение и задать
коды отсутствующих ответов по документации отдельно для каждого столбца.
Совпадение текстовое с удалением пробелов по краям и без учёта регистра:
«89» и «89.0» различаются. Автоматическое предположение не заменяет подтверждение.
Ограничения: 10 МиБ, 50 000 строк, 100 исходных столбцов, до 15 используемых.
План содержит 1–5 числовых показателей, одну операцию mean/median/sum и не более
одного категориального поля группировки. Максимум 30 групп; возможен расчёт по всем строкам.
Идентификаторы не используются как показатели или группировки.
Нули и отрицательные числа допустимы, если не объявлены кодами пропусков.
Пропуски, объявленные коды и нечисловые значения исключаются
из каждого показателя отдельно; число пригодных значений отражается в результате.
Строки без категории группировки исключаются и считаются отдельно.
При отсутствии пригодных чисел результат null, в том числе для суммы.

Не реализованы соединение таблиц, фильтры строк, веса, новые вычисляемые показатели,
корреляции, прогнозы, причинные выводы или сложные ведомственные шаблоны отчётов.
SPSS, Stata, Parquet, Python/R и блокноты не поддерживаются как входные файлы.
Из программ анализа сначала экспортируют таблицу в поддерживаемый формат.
Это ограниченный инструмент описательной статистики, а не универсальный исследователь.

3. Роль ИИ и проверка плана
Модель сопоставляет естественный вопрос с подтверждённой схемой и каталогом операций.
Она не вычисляет итоговые числа и не предоставляет исполняемый Python или SQL.
Программа проверяет структуру, допустимые поля, операцию и группировку.
При явно неверной операции модель получает ограниченную корректирующую попытку;
неподдерживаемый или неоднозначный вопрос не запускает расчёт автоматически.
Текстовые проверки не гарантируют понимание любого вопроса. Перед выполнением
пользователь видит показатели, операцию, группировку, период и отсутствие фильтров.
Подтверждение относится к сохранённому плану; выполнить произвольный план из запроса нельзя.

4. Контроль модели и данных
Локальная Ollama либо совместимый API выбираются в общих настройках приложения.
Настройки действуют также на прежний жилищный модуль. Внешний адрес требует HTTPS
и явного разрешения; автоматического перехода с локальной модели в облако нет.
Модель получает вопрос, подтверждённые названия/роли столбцов, единицы, единицу
наблюдения, период и каталог операций. Образцы, строки и результаты расчёта не передаются.
Вопрос и метаданные сами могут содержать чувствительные сведения.
API-ключ хранится только в памяти процесса; настройки без ключа — на диске.
Это один локальный пользователь, не реестр разрешённых моделей организации.
Роли, многопользовательский доступ, контроль малых групп и ведомственная аттестация
не реализованы. Агрегирование само по себе не гарантирует конфиденциальность.

5. Воспроизводимость и проверки
Исходный файл, нормализованный CSV, описание набора, план и отчёт сохраняются.
Проверяются хеши источников и версия расчётного кода. После скачивания Python и
source.csv расчёт повторяется командой python reproduce_table.py source.csv.
Для повторения нужны только Python 3.10+ и стандартная библиотека, без модели.
Загружаемый пользователем код не исполняется. Текстовые ячейки CSV результата
экранируются для электронной таблицы. Зафиксированный нормализованный source.csv
выгружается для Python без дополнительного экранирования и может содержать
формулоподобный текст; это отдельная машинная выгрузка.
Проверены числовые крайние случаи, ограничения планов, отсутствие строк в промпте,
выгрузка и отдельный запуск Python с совпадением результата и проверкой хеша.
Эти проверки не являются оценкой качества произвольной языковой модели.

Примеры examples/import/: schools.xlsx — 24 вымышленные школы, 2025 год;
budget.html — 12 вымышленных учреждений, 2025 год. У них разные столбцы и единицы;
оба набора обрабатываются одним механизмом через подтверждение паспорта.
Эти данные и результаты не являются официальной статистикой.
Новая проверка: reports/final_acceptance.json — 9/12 ожиданий; повтор после
исправления проверки неоднозначной операции — final_acceptance_regression.json,
10/12 на тех же вопросах. Выполнены 6/8 поддержанных задач, числа совпали с эталоном.
Два плана с лишним показателем остановлены для уточнения. Все три неподдержанных
запроса и неоднозначная операция в повторе не допускаются к расчёту.
Это открытая внутренняя проверка, не независимая оценка точности модели.
Исторические метрики жилищного модуля не характеризуют качество нового сценария.

6. Прежний модуль и MCP
/housing/ сохраняет предметный анализ D006/D008 за 2024 год и связь двух форм.
Его отдельная проверка qwen3:1.7b дала 18/20 открытых сценариев; вопросы использовались
при настройке, поэтому это не независимая точность. См. reports/local_mvp_validation.json.
Эту метрику нельзя переносить на главный экран с новым импортом.
Старый контроль качества и эксперимент Isolation Forest также не доказывают пользу
нового процесса; преимущество ML над робастным отбором ранее не подтвердилось.

MCP-прототип предоставляет только describe_housing_dataset, preview_housing_brief,
calculate_housing_brief для фиксированного жилищного расчёта. Общий импорт таблиц
через MCP не реализован. Модель и передача результатов определяются MCP-клиентом;
локальный процесс сервера не гарантирует, что внешний клиент хранит данные локально.
WhatsApp, Telegram, почта и ведомственные программы не подключены.

7. Пример анализа и область проверки
Анализ синтетических D006/D008 выполнен в главном интерфейсе с настоящей локальной
моделью: отдельный предметный скрипт подготавливает таблицу, затем пользователь
импортирует её, подтверждает паспорт и план, получает справку по 11 658 домохозяйствам.
До импорта исключены 46 записей с жилой площадью больше общей; синтетика, без весов.
Порядок повторения: docs/COMPETITION_CASE.txt. Контрольные результаты, независимая
сверка и полный протокол: reports/final_release_validation.json и связанные файлы.
Учебные школы и бюджет дополнительно демонстрируют переносимость импорта.

Дальнейшая приёмка: новые заранее зафиксированные вопросы по новым таблицам,
правильные планы либо обоснованные отказы, сверка чисел и самостоятельное получение
справки пользователем. Отдельно измеряются время, ошибки и необходимые исправления.
Внутренняя проверка команды не является пилотом БНС. Экономия времени,
применимость в ведомственных процессах и качество новых задач пока не измерены.
