# Residual

Residual — локальный ИИ-ассистент для подготовки описательных статистических справок. Специалист определяет смысл данных и подтверждает план анализа; программа рассчитывает показатели и сохраняет результат вместе с методикой и кодом для воспроизведения.

**Команда Residual:** Сагитов Алемхан Сагитулы, Голобородко Родион Максимович. **Трек:** AI for Official Statistics.


[Запуск и демонстрационный сценарий](docs/QUICK_START.txt) · [Данные и методика исследования D006/D008](docs/COMPETITION_CASE.txt).

**Результаты работы:** [аналитическая справка HTML](reports/competition_example_brief.html) · [протокол проверки](reports/final_release_validation.json). Анализ выполнен в основном интерфейсе с локальной моделью на 11 658 домохозяйствах синтетического массива D006/D008. Показатели сверены независимым расчётом и воспроизведены экспортированным Python-кодом. HTML-справка открывается в браузере после сохранения файла.

Рабочий цикл: **таблица → описание столбцов → вопрос → подтверждённый план → расчёт и справка**. Приложение работает с одной выбранной таблицей CSV, TSV, Excel или HTML; новый набор не требует изменения кода приложения.

Модель предлагает показатели и операцию. Программа проверяет план и считает после подтверждения специалиста. Справка начинается с ответа и рассчитанных значений; содержит таблицу, диаграмму, численность, пропуски, методику, ограничения и происхождение данных. HTML-справка с диаграммой открывается отдельно от приложения. Исходные файлы не изменяются.

## Запуск на Windows

1. Установите **Python 3.11–3.13** с [python.org](https://www.python.org/downloads/), отметив **Add python.exe to PATH**. Распакуйте репозиторий в обычную папку с правом записи.
2. Откройте **start_residual.cmd**. Первый запуск создаёт отдельную среду и устанавливает зависимости; затем открывается [приложение](http://127.0.0.1:8766/).
3. Для локального ИИ один раз откройте **setup_local_ai.cmd**. Дождитесь установки переносимой Ollama и модели **qwen3:1.7b**, затем проверьте подключение в настройках приложения.
4. Загрузите файл, выберите таблицу и подтвердите её описание. После этого задайте вопрос и проверьте план перед расчётом.

Далее запускайте **start_residual.cmd**; остановка — **stop_residual.cmd**. Для локального режима не нужны хостинг, Docker или платный API-ключ. Интернет нужен при первоначальной установке: около 1,5 ГБ загрузки и 3 ГБ места для CPU-варианта. Скорость модели зависит от компьютера. Подробности: [LOCAL_START.txt](docs/LOCAL_START.txt).

В новой установке нет загруженных таблиц и расчётов. Учебный пример запускается только по вашей кнопке и явно отмечается в результате. Сохранённые наборы тоже открываются по выбору. Проверены установка в новой среде, полный сценарий с настоящей моделью, отдельное воспроизведение и изменение результата при изменении файла: [проверка локальной версии](reports/local_validation.json).

## Конкурсный сценарий

Внутренняя жилищная справка: сравнить медианную площадь на человека по группам размера домохозяйства. Из синтетических D006 и D008 за 2024 год готовится одна таблица с проверкой ключей, состава и площадей; затем она загружается в главное приложение. Подготовка отделена от ИИ, воспроизводится кодом и сохраняет аудит источников и исключений. [Пошаговый маршрут и контрольные числа](docs/COMPETITION_CASE.txt).

В выданном архиве подготовка оставила **11 658 из 11 704 домохозяйств**: 46 записей с жилой площадью больше общей исключены по явному правилу проекта. Медианы площади на человека — **37; 18,666667; 12,666667 м²/чел.** для групп 1–2, 3–4 и 5+ человек. Все подготовленные строки и агрегаты сверены отдельным расчётом pandas из исходных форм. Это описательные числа синтетического набора, без весов и выводов о населении. Архив и подготовленные записи в публичный репозиторий не входят.

## Быстрая проба без конкурсного архива

На главной нажмите «Попробовать пример» или во вкладке **Данные** — «Открыть пример Excel». Можно выбрать файл [schools.xlsx](examples/import/schools.xlsx): 24 вымышленные школы, 2025 год. Выберите лист **«Школы (учебные данные)»**, строку заголовков **1**. Вопрос и план находятся во вкладке **Исследование**, готовые результаты — в **Справках**, подключение ИИ — в **Модели**.

В паспорте набора укажите: одна строка — школа; период — 2025. Проверьте роли: «Код школы» — идентификатор, «Тип школы» — категория, «Учащиеся» и «Учителя» — числа в человеках. Предложения программы требуют вашего подтверждения. Для своих синтетических файлов отметьте **«Это синтетические или учебные данные»**; встроенные неизменённые примеры распознаются также по содержимому.

Пример вопроса: «Сравни среднее “Учащиеся” по “Тип школы” за 2025 год». Проверьте, что план выбрал среднее, нужный показатель и тип школы, затем подтвердите расчёт.

Второй предметный пример — [budget.html](examples/import/budget.html): 12 вымышленных учреждений, 2025 год. Выберите таблицу **«Бюджет учреждений (учебные данные)»**, строку 1. «Регион» — категория; «Расходы» и «Поступления» — числа в тысячах тенге, для «Расходы» десятичный разделитель — запятая. Вопрос: «Сравни сумму “Расходы” по “Регион” за 2025 год».

Оба набора синтетические и служат проверке работы, а не выводам о населении или бюджете Казахстана. Для проверки динамики измените одно число в копии файла, загрузите её как новый набор и повторите вопрос о среднем или сумме. Одна правка может не изменить медиану.

Оба примера проверены через браузер с настоящей локальной qwen3:1.7b: план, подтверждение, расчёт, история и выгрузки. Числа сверены отдельно; скачанный Python повторил результат HTML-примера. Первый запуск на школах дал ложный отказ; после уточнения правил планирования тот же вопрос прошёл. Это проверка двух открытых сценариев, а не показатель общей точности модели. [Протокол проверки](reports/tabular_mvp_validation.json).

## Что поддерживается

- CSV, TSV, `.xlsx`, `.xls`, HTML/HTM с таблицами. В Excel выбирается лист, в HTML — таблица; строка заголовков задаётся явно.
- Одна таблица за расчёт: до **10 МиБ**, 50 000 строк, 100 исходных столбцов и **15 используемых столбцов**.
- От **1 до 5 числовых показателей**, одна операция — **среднее, медиана или сумма**; без группировки либо по одному категориальному полю, максимум **30 групп**.
- Подтверждённые названия, роли, единицы, десятичный разделитель и коды пропусков по документации столбца. Нули и отрицательные значения участвуют, если явно не объявлены пропусками. Пропуски и нечисловые значения отражаются отдельно; число пригодных значений считается по каждому показателю.
- История справок и выгрузки HTML, CSV, JSON, Python и исходного CSV для воспроизведения.

В поле **«Коды отсутствующих ответов»** перечислите подтверждённые документацией значения через точку с запятой. Программа не угадывает числовые служебные коды. Совпадение текстовое: `89` и `89.0` различаются, регистр и пробелы по краям не учитываются. Код из одной формы нельзя автоматически переносить в другую. Отметка синтетического происхождения сохраняется в наборе и справке.

В основном анализе не поддерживаются произвольные соединения таблиц, фильтры строк, веса, новые вычисляемые показатели, произвольные методы исследования, прогнозы и причинные выводы. Для конкурсных D006/D008 есть отдельный явный скрипт подготовки. Шаблоны сложных ведомственных отчётов не реализованы. SPSS, Stata и Parquet пока не принимаются: сначала экспортируйте таблицу в поддерживаемый формат. Python, R и блокноты не исполняются при импорте.

## Проверка ИИ и расчётов

На 12 заранее зафиксированных открытых внутренних заданиях с настоящей **qwen3:1.7b** первый проход дал **9/12**: [исходный протокол](reports/final_acceptance.json). После исправления обработки запроса без указанной операции повтор на том же наборе дал **10/12**: [регрессионный протокол](reports/final_acceptance_regression.json).

- Выполнены **6 из 8 поддержанных задач**; числа, численности и пропуски сверены независимым расчётом.
- В двух поддержанных задачах модель добавляла лишний показатель. Приложение остановило расчёт и запросило уточнение; эти задания засчитаны как неуспешные.
- **3 из 3 неподдержанных запросов** отклонены, неоднозначный запрос без операции требует уточнения. Это поведение приложения вместе с ограничениями кода, не показатель надёжности отказа одной модели.

Это повторная проверка на известном открытом наборе после исправления, **не независимая оценка общей точности и не пилот БНС**. Вопрос и предложенный план должен проверить специалист. Экономия времени и регулярная полезность для сотрудников ещё не измерены.

## Воспроизведение справки

Скачайте **Python** и **CSV для Python** из одной справки в одну папку. Запустите:

```bash
python reproduce_table.py source.csv > result.json
```

Достаточно Python **3.10+**, только стандартная библиотека; модель и приложение не нужны. Код проверяет SHA-256 источника и повторяет утверждённый расчёт. Это выгрузка доверенного кода приложения, а не выполнение загруженного или сгенерированного моделью Python.

`source.csv` содержит зафиксированную нормализованную таблицу для машинного воспроизведения и может содержать формулоподобный текст; он предназначен для Python. Для просмотра результата в электронной таблице используйте отдельную выгрузку **CSV результата**, где текстовые ячейки экранируются.

## Модель и данные

Настройки модели общие для главного экрана и жилищного модуля. По умолчанию используется локальная Ollama (`http://127.0.0.1:11434`, `qwen3:1.7b`). Можно выбрать другую загруженную локальную модель либо сервер с совместимым API и поддержкой JSON Schema. Внешнее подключение требует HTTPS и явного разрешения; автоматического перехода в облако нет.

Модель получает **вопрос, подтверждённые названия и роли столбцов, единицы, единицу наблюдения, период и каталог операций**. Образцы, исходные строки и результаты расчёта ей не передаются. Сам вопрос и метаданные могут содержать чувствительные сведения. API-ключ хранится только в памяти процесса; после перезапуска его вводят снова.

Данные, настройки без ключа и отчёты находятся в `private_outputs/`; папка исключена из Git. Переносимая Ollama запускается локально с отключёнными облачными функциями. Для отдельно установленной Ollama применяются проверки локального источника модели; подробности в инструкции запуска.

## Предыдущий жилищный модуль и MCP

Предыдущий анализ D006/D008 за 2024 год сохранён по адресу [/housing/](http://127.0.0.1:8766/housing/). Его встроенный интерфейс соединения двух форм и фиксированный каталог показателей относятся к этому модулю. Конкурсный маршрут для нового главного приложения описан выше.

Результат прежней открытой проверки **18/20** относится исключительно к жилищному сценарию с qwen3:1.7b: [протокол](reports/local_mvp_validation.json). Он не оценивает новый анализ произвольной поддерживаемой таблицы. Вопросы использовались при настройке; это не независимая оценка точности. Новый сценарий имеет отдельную проверку, описанную выше; результаты старого модуля на него не переносятся.

Опциональный MCP-сервер также обслуживает только фиксированный жилищный пример: `describe_housing_dataset`, `preview_housing_brief`, `calculate_housing_brief`. Он не открывает общий импорт таблиц, не содержит модель и не подключает мессенджеры. Для запуска нужны конкурсный архив и дополнительные зависимости:

```bash
python -m pip install -r requirements.txt -r requirements-mcp.txt
python -m src.mcp_server --data-dir "../synthetic_microdata_2021-2024_20260921"
```

Модель и передача результатов управляются внешним MCP-клиентом. [Пример конфигурации](docs/mcp_local_example.json) требует путей вашего компьютера.
